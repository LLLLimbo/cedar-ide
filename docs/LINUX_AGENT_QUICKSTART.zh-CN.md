# Linux 远程 agent 开发包

这是 Cedar 的无界面 `cedar-agent`，供已有 SSH 工作区使用。它不是完整桌面 IDE、安装器、系统服务或通用 Linux 静态二进制。包未签名；哈希可核对文件完整性，不等于发布者签名，也不证明可复现构建。

## 支持范围与运行条件

本包只针对 **Ubuntu 24.04、amd64 / x86_64、glibc** 构建和验收。`BUNDLE_MANIFEST.json` 记录实际 ELF 解释器、所需共享库、GLIBC 符号版本以及源提交和 CI 运行。验收核对的是包中二进制本身，不能用另一台机器的运行结果替代。

需要兼容的系统动态加载器、glibc 和 libgcc 运行库。不要把此包当作 Alpine/musl、ARM64、旧版 glibc 或任意 Linux 发行版均可运行的程序；不兼容时应使用适配目标环境的构建。不要复制其他机器的 glibc 到系统目录来绕过兼容性问题。

运行基本文件协议不需要 Rust、Python、图形桌面、OpenGL、JDK 或 JVM。Git、语言服务和构建命令需要工作区主机上另行存在相应工具。本包不包含这些工具，也不会自动下载或安装它们。

## 包中有什么

- 正常默认构建的 `cedar-agent`，归档中的执行权限为 `0755`
- 本说明、逐文件 SHA-256 / 大小 / 权限清单与源提交、CI、ELF 要求记录
- [项目 MIT 许可](LICENSE-MIT)、[Apache 许可](LICENSE-APACHE)、[第三方说明](THIRD_PARTY_NOTICES.md) 和 `third-party-licenses/`

第三方许可来自当前工程收集的许可清单，可能涵盖未链接进此单个程序的组件；这不是运行时依赖清单。包不包含桌面前端、测试夹具、诊断驱动、凭据或项目文件。

## 准备与连接

1. 从对应源提交的项目 CI 获取归档，并核对提供的归档 SHA-256。保留 `BUNDLE_MANIFEST.json`，不要混用不同提交的清单和二进制。
2. 解压到自己选择的**新空目录**。tar 归档保留程序执行权限；不要覆盖已有用户配置或系统程序。验收要求在包含空格和 Unicode 字符的目录中解压，但这不替代目标系统 ABI 检查。
3. 按你既有的部署方式，将 agent 放在你控制的远程主机路径。Cedar 不会替你上传、安装、注册服务或修改 SSH 设置。本文不表示这些操作已经发生。
4. 在前端的 **Open workspace → Remote over SSH** 中填写已有 SSH 主机/别名、远程 agent 可执行文件路径和绝对工作区目录。使用已配置的系统 OpenSSH；应先在自己的终端完成身份认证和主机密钥核验。Cedar 不关闭主机密钥检查、不创建 SSH 密钥、不启动 sshd，也不建立新的监听端口。
5. 先保持执行信任关闭。连接后可以使用后端已声明支持的文件浏览、读取、编辑、保存和文本搜索。保存会修改所选工作区文件；执行信任关闭并不等于只读模式。

agent 接收 `--root PATH`，通过标准输入/输出处理协议帧，通常由前端的 SSH 会话启动。它没有登录界面或常驻网络服务。不要把普通终端文本或程序日志写入它的协议标准输出。

## 执行信任与平台差异

能力声明说明兼容性，不授予执行权限。任务、Git 和语言服务仍需要用户显式信任工作区；相关工具可能以当前账户权限运行项目代码，不是安全沙箱。不要为不可信项目启用执行信任。

Linux 独立 agent 提供异步命令任务、显式 Git、通用 LSP 和基本类型化 Java/JDT。类型化 Java 需要匹配版本的前端、工作区执行信任及主机上已安装的 JDK/JDT；面向库调用者的 Linux Client Local 内嵌工作区仍只提供通用 LSP；0.41 GUI Local 使用匹配的同目录独立 agent（本阶段待验收）。0.39.1 显式 Maven 叶工程启动、模型和依赖快照已通过精确 Ubuntu 原生验收；需要匹配的能力分组前端及已有缓存，详见 [Maven 范围与限制](MAVEN_PROJECTS.md)。离线依赖解析不等于网络隔离，信任允许工具按当前账户权限运行。前端以当前握手能力为准，不会自动启动服务。完整 Maven/Gradle 工程、交互式 PTY 和 IDE 调试桥接不在本包范围。

Linux 通用 LSP 的父进程管道由单个所有者管理。内部清理记录区分自然退出与强制清理，通用 Stop 回执仍为原有格式；固定退出宽限结束或清理触发后，调用方最多观察三秒清理完成，线程调度与最终 join 不属于硬实时保证。超过观察期会报告清理未验证，原所有者继续承担等待职责，不会再次根据旧 PID 猜测发送信号。同一工作区禁止重新启动语言服务，草稿不变；显式重连也不能证明旧进程已退出，应先确认旧服务的清理情况。

进程组清理不等于沙箱，也不证明所有后代均消失：逃逸进程组、变更凭据、agent 被突然终止，以及不可中断的内核等待不在保证范围。宿主不能同时使用其他 SIGCHLD 回收器、SIGCHLD=SIG_IGN 或 SA_NOCLDWAIT 来抢先或自动回收 agent 所拥有的语言服务。执行信任被撤销后，仍可请求清理已经拥有的 Linux 语言会话，但不能再启动或查询服务。

前端与 agent 的协议版本必须相符。产品版本用于识别构建，操作可用性仍由能力协商控制；本包只对清单所列源提交和实际 CI 验收负责，不承诺任意旧前端兼容。

## 断开与验证边界

停止活动语言服务、取消任务并等待其终态后，可在前端主动断开空闲连接。草稿留在前端，保存结果不明时不会自动重写。`Disconnecting` 等待本地所有者清理回执；`Cleanup unverified` 不能当作成功清理。显式重连不会证明旧远程进程已经退出。

本包验收使用本地标准输入/输出启动解压后的精确 agent，在新建的合成工作区中检查协议、文件操作、版本冲突、路径边界、执行拒绝、退出回收和重新连接，并核对包文件未改变。**这不等于真实 SSH 身份认证、Windows 到 Linux 联机、网络断线恢复或远程进程清理验收**；也不包含原生 GUI 测试。没有接触用户项目或用户电脑。

## Linux 类型化 Java 配置

在已连接的 Linux 独立 agent 会话中，显式填写主机上的真实绝对 `java` 可执行文件路径、包含 `plugins` 与 `config_linux` 的 JDT 发行目录，以及工作区之外已存在的专用数据目录。不要填写 PATH 名称、脚本包装器或 `/usr/bin/java` 这样的符号链接；选择 JDK 实际安装目录中的 `bin/java`。支持空格和 Unicode 路径。前端不会代为下载 JDK/JDT、创建数据目录或更改环境变量。

固定堆上限为 512 MiB，但 JVM 的总内存可能明显更高。Maven/Gradle 自动导入关闭并不等于网络或进程沙箱。数据和 JDT 配置可能写入缓存；只对可信发行版及工作区启用执行。

Stop 显示 Linux 原始退出码或信号，强制清理不会显示为自然退出。经过验证的清理即使伴随协议错误也允许重新启动；清理未验证时会保留草稿并阻止同一工作区重启。先核对旧服务清理，再显式重连，重连本身不是退出证明。旧版前端可能拒绝 Linux 类型化 Stop 的新回执，应与本包使用同一版本前端。

## 连接字段

前端的端口是显式覆盖值，即使主机填写 SSH 配置别名，也会使用此端口而非别名中的 Port。填写远程路径的字面量；`~` 和 `$变量` 不会展开。建议 agent 使用绝对路径，例如 `/home/you/tools/cedar-agent`；裸名称依赖远程命令环境。连接前会在本机内存中检查字段语法，不能据此证明主机可达、文件存在或身份认证成功。
