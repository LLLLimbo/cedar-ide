## Unchanged Automatic height contract

The existing 0.56.1 height behavior remains: a genuine primary-button vertical drag on the native top divider establishes a runtime preference. That choice survives report loading/clearing, tool switches, hide/show, disconnect and reconnect. Window constraints can limit the displayed allocation without overwriting the preference; regrowth restores it when space permits. Passive hover/click, horizontal movement and another control's drag do not establish a preference. The 245-point default and 150–500 range are unchanged, and neither a hard content cap nor guaranteed editor space is promised.

The new **Automatic height** action explicitly clears the runtime preference after the current panel pass and requests repaint. Subsequent layout uses the existing automatic content-sizing path; resetting does not substitute a fixed height, persist a setting or require restarting the app. A later genuine divider drag can establish an explicit preference again. The control is disabled when the panel is already automatic.

Reset takes precedence over divider capture for the current input frame and every layout pass in that frame. If Primary is still down, reset retains a wait-for-release guard. An existing wait is preserved even across focus loss. The original raw-input hook observes an actual Primary release to clear that wait for future frames; a release/repress batch stays blocked for its current frame. PointerGone or focus loss does not invent a release. A subsequent genuine Primary press/release sequence can recover the guard without synthesizing a release, and a later independently owned divider-drag frame may capture a new height. This prevents a stale held drag or another layout pass from immediately undoing reset while preserving a fresh real drag.

The existing wrapped tools header also gains a small preventive fit guard for the native close/reset group. It measures both small buttons using their actual font/style, conditional horizontal frame padding and item spacing; the inside border does not add layout width. Only when the remaining row cannot fit the group does it end that row before creating the unchanged right-to-left group. Right alignment, native control order and normal button sizing remain intact. This addresses a source-review risk, not an observed runtime failure, and does not redesign other layouts. Production-frame coverage includes the 780×540 viewport at 13- and 18-point fonts plus normal width; the corresponding 0.58.0 resize checks passed on both CI platforms, within the failed aggregate run.

The action must preserve drafts, selection, Undo/Redo, saved baseline, editor/navigation versions and location history; accepted report identity, revision, filters, selected case and details; and pending operations and connection ownership. Height state is local UI state. Reset must queue no workspace operation, Read, Write, Search, task or language action.
