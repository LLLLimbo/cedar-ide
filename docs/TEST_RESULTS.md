# 显式读取 Java 测试报告

0.23 的 **Tests** 面板读取已有 Surefire/JUnit 风格 XML 文件，显示测试用例、状态、
耗时和失败详情。它是报告阅读器，不是测试运行器，也不会证明工作区当前版本通过测试。

## 使用

1. 连接工作区，保持执行信任关闭也可以使用。
2. 打开 **Tests**，输入一个工作区相对路径，例如
   `target/surefire-reports/TEST-example.ExampleTest.xml`。
3. 显式点击 **Load report**。需要更新同一路径时点击 **Refresh report**；不会扫描目录或在后台轮询。
4. 按状态或名称筛选，并选择一条用例查看详情。**Clear report** 清除面板中的结果。

读取沿用普通工作区 `Read` 的根目录、符号链接、UTF-8 与大小边界。绝对路径、上级目录
跳转和不支持的路径形式会被拒绝。输入使用 `/` 分隔目录；不会执行或展开路径中的内容。
没有自动测试、依赖下载、语言服务启动、文件写入或 Save All，也不会自动打开编辑器标签。

## 报告含义与支持范围

当前支持 XML 1.0 / UTF-8、无默认命名空间的单个 `testsuite` 根元素及其 `testcase`。保留套件名、用例名、可选 classname、
有限非负耗时，以及 failure/error/skipped 的受限文本。耗时是报告写入的历史值，
不是 Cedar 本次测量；套件耗时不强行等同于用例耗时之和。

失败、错误、跳过和普通通过分开显示。rerun/flaky 记录显示为 **Unsupported / flaky**，
不能因为缺少普通 failure 节点就显示为通过。零用例报告只表示读到了空报告。
重复用例名不会被合并。报告声明的计数必须符合支持的解析规则；未知结构、畸形或不完整 XML、
无效数值和超限输入不能成为部分成功报告。显示计数按可见状态统计；Unsupported 用例
单列，不混入 Passed。声明的失败/错误/跳过计数仍依据普通结果节点独立核对。

DTD、自定义实体和外部资源解析均不支持。XML schema 位置仅作为格式元数据，不会被访问。
properties、system-out 和 system-err 会被丢弃，不进入结果快照或详情视图。
失败正文按普通文本显示，不执行 HTML、链接、命令或终端转义序列。

每份结果绑定连接代次、提交的精确路径、读取请求和磁盘 revision。修改路径、清除、更新读取
或重连后，晚到的旧响应不能覆盖新结果。显示的 revision 标识那次读到的字节，不代表文件
仍然未变；现有未保存编辑稿也不会变成这份报告的测试输入。脏稿、Undo 和恢复状态保持独立。
本阶段没有从 classname/堆栈猜测源码路径或跳转行号。

## 验证与资源

解析器复用已有锁定版本 quick-xml。源代码包含一份逐字保留的 Apache Maven Surefire 3.5.4
官方回归报告夹具，附来源、Git blob、SHA256 和许可证；这证明该夹具的解析兼容性，
不声称 Cedar 运行了 Surefire、JUnit 或 Maven goal。
两平台的显式进程验收使用正常 agent、信任关闭和自建文件，验证读取、历史 revision、
过期响应、重连、错误报告、草稿与输入保持以及子进程回收。

输入最多 1 MiB，最多 4096 个用例、65536 个 XML 事件、深度 8；字符串保留总量
最多 256 KiB。属性、文本、详情数另有独立限制，超过任一限制时整份报告不加载。
一次只保留一份有界结果，最多两个未完成的读取请求，不建立后台索引或长驻测试进程。实际通过范围以同提交 CI 为准；
不因此声称原生 GUI、真实 SSH 或任意 JUnit XML 方言已验证。
