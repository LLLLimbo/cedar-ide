# Java 编译位置 · 0.21

Commands 中的 **Extract javac locations** 显式解析最近一个已完成任务保留的
stdout/stderr。它只查看已有输出；不会启动编译器、语言服务、保存文件或重跑任务。
运行命令仍需要原有的执行信任与明确的 executable/argv。

## 使用范围

先用 Commands 明确运行自己的编译命令，等待终态，再提取位置。结果绑定到实际
提交的命令、工作区和连接，而非随后修改的表单。新任务或重新连接会使旧结果失效。
原始有界输出仍可查看；解析失败或结果为空不表示编译成功、没有错误或源码正确。

初版只识别这一种英文 javac 文本形状：

```text
src/示例.java:12: error: incompatible types
src/Example.java:8: warning: unchecked conversion
```

行号必须为无前导零的正十进制整数，且不超过 `u32::MAX`；文件名以 `.java` 结尾。
stdout 与 stderr 分开记录原输出行号，
不推断两条流的时间顺序，不用源码下方的 `^` 推断列。多行说明、堆栈、彩色输出、
本地化消息和 Maven/Gradle 包装格式不在本次语法范围。工具不会根据程序名猜测格式。
输出由可信工具提供，但其中的路径仍需通过独立检查。

最多保留 256 行，单路径 4 KiB、单消息 2 KiB、保留文本合计 512 KiB；
每流最多扫描 768 KiB（覆盖捕获内容经过有损 UTF-8 解码的膨胀上限）。
跳过、截断和未扫描内容会明确显示；控制字符和方向控制符所在的位置行被拒绝。
任务本身仍遵循每条流 256 KiB 的既有捕获上限。提取操作不是持续监听或项目索引。

## 打开位置与草稿

只有可验证的工作区相对路径可点击。Windows 后端的普通分隔符可转换为协议形式；
按后端平台解释路径，不使用前端机器的文件系统规则。绝对路径、盘符相对路径、
UNC/设备路径、URL、父目录跳转与不支持的拼写可显示但不能导航。
百分号序列是字面文件名，不按 URL 解码。

打开文件使用既有工作区 Read 边界，继续拒绝越界或符号链接。路径拼写一致的已打开
草稿被复用，不被磁盘内容覆盖，撤销历史保留。Windows 上检测到 ASCII 大小写变体与已打开
路径冲突时拒绝跳转，不擅自合并可能位于大小写敏感目录的文件。此功能没有新增物理
文件身份协议，不能识别所有 Unicode 大小写、硬链接、短名称或其他文件别名。
编译位置是历史行号：编译器读到的磁盘内容可能
与现在的文件或未保存草稿不同。超出当前文本范围的行号会提示过期/不可定位，不能
被默默当作当前最后一行的准确诊断。标签数量与晚到读取响应仍受原有保护。

Commands 会提醒存在未保存草稿；Run 不隐式保存，位置提取也不执行 Save All。
用户仍需自行决定何时保存、编译以及如何处理编译器产生的文件。

## 编译器与验证边界

无需 JDT LS 即可提取已有输出，但运行 javac 需要用户自行安装和选择 JDK。
本功能不发现项目、下载依赖、加载构建插件或配置注解处理器。普通命令任务保留用户
明确选择的参数和环境，不把测试中的编译参数自动加入用户任务。

合成验收使用明确选择的 JDK 21 javac、英文消息和 `-proc:none`，通过正常 agent
任务与文件读取路径验证。`-proc:none` 在该夹具中关闭注解处理；其含义见
[官方 javac 文档](https://docs.oracle.com/en/java/javase/21/docs/specs/man/javac.html)。
编译器可在合成输出目录生成文件，验收单独检查源文件未变。
原生 GUI 开启信任及真实 SSH 认证仍是独立的待验证范围。
