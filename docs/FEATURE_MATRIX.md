## 本阶段验收边界

- 第四阶段最终本地聚合通过：fmt、严格 Clippy、336 个普通测试 + 1 个显式 agent 测试、三条 Python 黑盒链。4 个聚合 opt-in 忽略，其中 agent 随后单独执行；前端 171 项、恢复 37 项均已包含在总数中
- 首次聚合的恢复 drop/reopen 锁失败与导航后撤销/混合输入顺序已修复并纳入回归；最终 Linux release 原生窗口的 Escape、Apply、光标/标签导航后单步撤销与重做复验通过，历史失败日志保留
- 公开第三阶段 Windows CI 暴露并发恢复替换 AccessDenied，Linux 因 fail-fast 被取消；独立 phase-3.1 修复已发布，同一提交的 Linux/Windows CI 全通过，含 29 个 Windows 恢复测试、release 构建和 stdio 集成；这是核心运行证据，不是原生 GUI 验收
- 真实 JDT 经独立 stdio agent 完成 10 项检查：两份未保存草稿的跨文件引用、实际类/方法大纲、中文格式化、精确旧版本拒绝、格式化幂等、URI 越界拒绝、关闭/停止和项目源码磁盘不变
- 首次冷启动引用请求触及 10 秒 LSP 请求期限；干净重跑通过。脚本可在有界准备窗口显式重试只读请求，正常 UI 不自动重试；这不是延迟或稳定性基准
- Linux 原生候选窗口已验证只读格式化预览、显式 Apply/Cancel、立即撤销/重做、类/方法大纲与跨文件引用跳转，脏目标保留且源码磁盘不变；该候选早于最终审阅修复，后续 release 专项复验与两份源码磁盘不变的证据见 [测试报告](TEST_REPORT.md)
- 第三阶段恢复/命令原生验收与资源读数、第二阶段 Kotlin/debugpy 证据保留为历史，不冒充本轮重复验收。Windows CI 核心测试不是原生 GUI 验收

## 建议下一顺序

1. 完成当前阶段可靠性验收与真实项目回归，保留格式化/引用/大纲的严格 URI、UTF-16、版本和脏稿边界。多文件重命名暂缓：先设计无版本跨文件快照、跨文档撤销，以及服务器可能省略文件重命名的处理，见 [重构路线](REFACTORING_ROADMAP.md)
2. 可靠性补齐：真实 SSH 认证/断线恢复测试、外部文件监听/冲突体验、Windows Job Object 与可取消管道、多平台恢复与编辑验收
3. Java/Kotlin 工程导入：真实大型 Maven/Gradle 项目、JDK 选择与索引进度；先解决官方 Kotlin 许可/安装阻碍，再验证兼容性
4. DAP 调试 UI/agent、PTY、测试树；先解决监听安全和普通后代进程回收，再以真实程序端到端验收
5. Git/插件协议与框架工具，按实际需求逐项实现；在等价功能集下建立可复现性能基线

上述路线不是已经实现的功能或交付承诺。完成后仍不能直接宣称与 IntelliJ IDEA 全功能等价，需要持续维护兼容矩阵、真实测量与长期项目使用反馈。
