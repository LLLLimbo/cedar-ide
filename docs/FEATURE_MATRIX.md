## 本阶段验收边界

- 244 个普通测试、额外 1 个独立 agent 测试及文件/LSP/异步任务三条黑盒链通过；4 个 opt-in 测试在聚合阶段忽略，agent 随后单独执行
- Linux 原生窗口已验证中文草稿确认备份后强制结束、启动显式恢复、信任关闭、保留版本冲突和丢弃清理
- Linux 原生窗口已验证长命令的实时输出，以及 Running 时打开、编辑并保存另一文件；重连触发 Cancel-and-wait 保护；关闭提示后使用 Commands Cancel，并在原生界面确认 Cancelled，终态后重连未自动重跑。提示窗口内的取消按钮未人工验收
- 第二阶段真实 JDT、Kotlin、DAP 和内存读数保留为历史证据，不能表述为本轮重测；第三阶段独立 release 前端样例观察到 HWM 117.97 MiB，不构成恢复开销或性能提升的对照结论

## 建议下一顺序

1. 安全语言体验：先做单文档格式化预览、引用查找与文档大纲；严格校验 URI/UTF-16/范围、版本与脏稿冲突，明确应用确认和撤销边界。多文件重命名暂缓：需先解决无版本跨文件响应的快照可信度，以及服务端因不支持文件资源操作而省略重命名的风险
2. 可靠性补齐：真实 SSH 认证/断线恢复测试、外部文件监听/冲突体验、Windows Job Object 与可取消管道、多平台恢复与编辑验收
3. Java/Kotlin 工程导入：真实大型 Maven/Gradle 项目、JDK 选择与索引进度；先解决官方 Kotlin 许可/安装阻碍，再验证兼容性
4. DAP 调试 UI/agent、PTY、测试树；先解决监听安全和普通后代进程回收，再以真实程序端到端验收
5. Git/插件协议与框架工具，按实际需求逐项实现；在等价功能集下建立可复现性能基线

上述路线不是已经实现的功能或交付承诺。完成后仍不能直接宣称与 IntelliJ IDEA 全功能等价，需要持续维护兼容矩阵、真实测量与长期项目使用反馈。
